## 背景

FastAPI + Mangum の Lambda アプリを、Python の依存パッケージとともに配布する。配布方式の選定では、実行環境の再現性に加え、セキュリティ更新を継続して適用するための管理負担を考慮する。

## 決定

- アプリと依存パッケージを ZIP にまとめ、Lambda の Python マネージドランタイムで実行する。
- ランタイム更新モードは `Auto` を使用する。

## 比較と採用理由

| 比較項目 | ZIP＋マネージドランタイム（採用） | コンテナイメージ |
| --- | --- | --- |
| ランタイムのパッチ適用 | `Auto` により AWS が適用 | 更新されたベースイメージから利用者が再ビルド・再デプロイ |
| Python の依存パッケージ | ZIP に同梱 | イメージに同梱 |
| イメージの保管・管理 | 不要 | ECR リポジトリとイメージを管理 |
| 実行環境のカスタマイズ | 管理ランタイムを前提とする | OS ライブラリなどをイメージで指定可能 |

このアプリは FastAPI と Mangum によるイベント処理を行い、独自の OS 構成を必要としない。ZIP 方式で必要な依存パッケージを配布できるため、実行環境のパッチ適用を AWS に任せられる方式を選ぶ。

ZIP のビルド環境と Lambda の配布方式は別の選択になる。ビルドに Docker を使っても、ZIP として配布すれば実行時はマネージドランタイムを使用する。

## 採用による影響

### 利点と制約

- 実行環境のパッチ適用を AWS に任せられ、ECR とベースイメージ更新の管理が不要になる。
- 管理ランタイムの OS・Python 構成を前提とし、同梱するネイティブ依存パッケージは Lambda の OS・CPU アーキテクチャに合わせる必要がある。
- ランタイムの自動更新による互換性への影響を考慮し、アプリの動作を確認する必要がある。

### 更新の責任範囲

| 対象 | 更新の担当・扱い |
| --- | --- |
| Lambda の実行基盤 | ZIP・イメージのどちらも AWS が管理 |
| 管理ランタイムに含まれる Python・OpenSSL など | AWS が提供するランタイム更新を `Auto` で適用 |
| アプリと同梱ライブラリ | 利用者が更新し、ZIP を再ビルド・再配布 |
| 同梱・明示指定する CA 証明書 | 利用者が更新。ランタイム更新によって自動で置き換わるものではない |

`Auto` は、特定の CA の不信頼化がいつ反映されるかを保証するものではない。証明書に関する問題への対応では、通信に使うライブラリと、実際に参照する CA ストアを確認する必要がある。
