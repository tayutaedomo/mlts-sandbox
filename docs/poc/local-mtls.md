## 目的と対象

AC と RA 間の HTTPS 通信で使うクライアント証明書認証を理解するため、Python と OpenSSL で TLS/mTLS を小さく実装して検証する。

`tls/` にはサーバー証明書を検証する HTTPS、`mtls/` にはクライアント証明書も検証する mTLS を、独立した学習例として実装している。mTLS は正常なクライアント証明書による接続と、証明書なし・非信頼 CA の証明書の拒否を検証する。AWS 上の構成や本番の AC 接続仕様は、このローカル検証の対象に含めない。

実行方法は [local-mtls/README.md](../../local-mtls/README.md) を参照する。この文書には検証の目的、仕組み、結果を残す。

## 現在の構成

1. OpenSSL で検証用の自己署名ルート CA を作る。
2. サーバー・クライアント用の秘密鍵と CSR（証明書署名要求）を作り、同じ CA でそれぞれの用途の証明書を発行する。
3. Python のサーバーが、サーバー証明書と秘密鍵を読み込んで待ち受ける。mTLS 版では、クライアント証明書の検証用 CA と `CERT_REQUIRED` も設定する。
4. クライアントが信頼する CA 証明書を指定し、サーバー証明書を検証する。mTLS 版では自分の証明書と秘密鍵も読み込み、相互に証明書を検証してから HTTP GET を送る。

| ファイル | 役割 |
| --- | --- |
| `ca.crt` | 相手の証明書の検証に使う CA 証明書。mTLS 版では両側が使用 |
| `ca.key` | サーバー・クライアント証明書の署名に使う CA の秘密鍵 |
| `server.csr` | サーバー証明書の発行を求める署名要求 |
| `server.crt` | CA が署名したサーバー証明書 |
| `server.key` | TLS サーバーが使う秘密鍵 |
| `client.csr` | クライアント証明書の発行を求める署名要求 |
| `client.crt` | CA が署名したクライアント認証用の証明書 |
| `client.key` | TLS クライアントが使う秘密鍵 |

手動実行用のファイルは `local-mtls/certs/generated/` に生成する。生成物は Git 管理対象外とし、設定ファイルとスクリプトから作り直せるようにしている。テストでは一時ディレクトリに生成し、テスト終了後に削除する。

## コードと証明書設定の対応

- [tls/server.py](../../local-mtls/tls/server.py) の `load_cert_chain` でサーバー証明書と秘密鍵を読み込み、`wrap_socket` で HTTP サーバーのソケットに TLS を追加する。
- [tls/client.py](../../local-mtls/tls/client.py) の `create_default_context(cafile=...)` で信頼する CA 証明書を指定する。証明書検証と接続先のホスト名検証を有効にして接続する。
- [mtls/server.py](../../local-mtls/mtls/server.py) では `load_verify_locations` でクライアント検証用 CA を読み込み、`CERT_REQUIRED` で証明書の提示と検証を必須にする。
- [mtls/client.py](../../local-mtls/mtls/client.py) では `load_cert_chain` で自分の証明書と秘密鍵を追加する。サーバー証明書の検証も行う。
- [generate-certs.sh](../../local-mtls/scripts/generate-certs.sh) で CA とサーバー・クライアント証明書を生成する。
- [server-ext.cnf](../../local-mtls/scripts/server-ext.cnf) は、署名時にサーバー証明書へ付ける X.509 拡張設定。`serverAuth` で用途を指定し、SAN に接続先の `localhost` と `127.0.0.1` を含める。鍵識別子も設定して、証明書チェーンの検証に使えるようにしている。
- [client-ext.cnf](../../local-mtls/scripts/client-ext.cnf) は、クライアント証明書の用途を `clientAuth` に限定する。`digitalSignature` で秘密鍵を持つことの証明に使い、鍵識別子を証明書チェーンの検証に使う。

## 検証結果

### 自動テスト

Python 3.13.17・pytest 9.1.1 のローカル環境で、次の5件が成功した。

| ケース | 期待する結果 | 確認結果 |
| --- | --- | --- |
| サーバー証明書を発行した CA をクライアントが信頼する | HTTPS 接続が成立し、応答本文を取得できる | 成功 |
| 別の CA をクライアントが信頼する | サーバー証明書の検証に失敗する | `SSLCertVerificationError` を確認 |
| サーバーが信頼する CA のクライアント証明書で接続する | mTLS 接続が成立し、応答本文を取得できる | 成功 |
| クライアント証明書を提示しない | サーバーが接続を拒否する | 証明書必須の TLS アラートを確認 |
| 別の CA が発行したクライアント証明書を提示する | サーバーが接続を拒否する | 非信頼 CA の TLS アラートを確認 |

[HTTPS のテスト](../../local-mtls/tests/test_tls.py) は別々の CA を生成して信頼関係の違いを比較し、[mTLS のテスト](../../local-mtls/tests/test_mtls.py) は証明書の提示有無と発行元による接続結果を比較する。非信頼 CA のクライアント証明書を試す場合も、クライアント側のサーバー検証用 CA は正常なままに保つ。拒否のテストでは TLS アラートの種類も確認し、接続拒否やタイムアウトなどの通信障害を認証失敗として扱わない。接続には `127.0.0.1` の一時ポートを使い、外部サーバーには接続しない。

### 手動確認

HTTPS 版で、サーバーの証明書と接続先を固定し、クライアントが信頼する CA だけを変えて接続結果を比較する。

| ケース | 操作 | 確認結果 |
| --- | --- | --- |
| 接続成功 | サーバー証明書を発行した CA を `--cafile` に指定 | 接続に成功 |
| 接続失敗 | 別のディレクトリに CA を生成し、その CA を `--cafile` に指定 | 接続に失敗 |

同じサーバーでも、クライアントが信頼する CA によって接続結果が変わる。操作手順は [README の証明書検証失敗の確認](../../local-mtls/README.md#証明書検証失敗の確認) を参照する。

mTLS では、サーバー証明書の検証用 CA を固定し、クライアント証明書の提示有無と発行元による接続結果を比較する。操作手順と期待する結果は [README の mTLS の確認](../../local-mtls/README.md#mtls-の確認) を参照する。

ホスト名不一致や有効期限切れは個別のテストにしていない。
